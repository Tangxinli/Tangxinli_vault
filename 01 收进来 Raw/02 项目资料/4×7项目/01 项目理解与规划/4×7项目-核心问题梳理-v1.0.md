## 一、理解校准：什么通用、什么本土

### 1.1 用户的理解

> "不同城市的客户画像、市场环境不同，所以经纪人的专业服务具体做法（4×7矩阵）、经纪人评价框架、经纪人所需具备的根能力、经纪人的成长曲线以及对应的培训赋能方向和相应的课件都不一样。"

### 1.2 更准确的判断

**框架是通用的，内容是本土的。**

| 层 | 通用（不变） | 本土（变） | 判断依据 |
|---|---|---|---|
| **L1 矩阵** | 4类能力×7阶段=28格的结构 | 每格内的具体交付物、关键动作、案例 | 结构来自578案例实证；内容需要本土案例填充 |
| **L2 水位** | Y轴/X轴定义、L1/L2/L3标准 | 一个城市经纪人的典型分布比例 | 标准跨市场通用；分布因城市而异 |
| **L3 根能力** | 8项根能力的定义和数量 | 哪些根能力是这个城市最缺的优先项 | 8项是横切28格的根能力，通用；优先项本土 |
| **L4 成长** | A/B/C三种曲线类型 | 具体经纪人的成长路径和培训策略 | 类型通用；策略本土 |
| **核心逻辑** | 完成=判断+路径 | 判断和路径的具体内容 | 定义通用；表现本土 |

**为什么这个区分重要**：

- 如果框架因城市而变 → 无法跨城市比较、无法复制、无法形成组织共识语言
- 如果只给框架不给内容 → 城市认为"空架子"，无法落地
- **共创的价值**：用通用框架 + 本土内容，形成既可比又落地的能力图谱

### 1.3 城市共创的本质

城市共创不是"每个城市建自己的框架"，而是：

> **每个城市用自己的内容，填通用的框架。**

通用层由花桥（你）提供：框架结构、评价标准、根能力定义、萃取方法
本土层由城市共创：具体案例、格内内容、优先提升项、培训课件

## 三、城市共创具体如何合作

### 3.1 合作模型

```
花桥提供（通用层）          城市共创（本土层）
─────────────────          ─────────────────
框架结构（4×7矩阵）    ←→   本土案例填充28格
评价标准（L1/L2/L3）   ←→   城市经纪人的典型分布
根能力定义（8项）       ←→   城市优先提升项
萃取方法（SKILL）       ←→   城市自己的案例萃取
培训方向（学-练-评）    ←→   本土化课件
```

### 3.2 合作节奏

| 轮次 | 花桥做什么 | 城市做什么 | 产出 |
|------|-----------|-----------|------|
| **第一轮**（6月18日） | 带框架+示范案例去 | 用自己的案例试填框架 | 共识框架 + 一个赛道雏形 |
| **第二轮**（7月） | 整合第一轮产出，迭代框架 | 完成双赛道 + 本土化调整 | 城市版4×7能力图谱V1 |
| **持续迭代**（8月起） | 基于多城数据优化框架 | 在实战中验证和补充 | 标准化共创SOP + 复制手册 |

### 5.2 在工作坊中如何使用

**定位调整**：付振博案例是Z1+Z2层面的L3示范，**不是完整的L3画像**。

在工作坊中，你应该：

| 用法 | 说明 |
|------|------|
| **教方法** | 展示"什么是能力拆解"，让大家理解框架如何使用 |
| **说明局限** | 坦诚说明"这是单次案例的水位判断，长期还需要验证" |
| **引出讨论** | "重庆有没有类似付振博的经纪人？你们怎么判断他是不是L3？" |
| **不要用来定标准** | 不要说"L3就是这样"——付振博是样本，不是标准 |

**关键引导话术**：
> "付振博这个案例，在单次服务中展现了L3的水位。但一个人是不是真正的L3，还需要看长期。我们今天先用他来练习拆解方法，然后请大家用重庆自己的案例来验证。"

## 六、案例萃取SKILL的理解

### 6.1 金燕的意思

"整合共识案例萃取的SKILL"——这里的SKILL不是"某一项具体技能"，而是：

> **一套标准化的案例萃取方法论——让4个人的萃取结果可比较、可整合。**

### 6.2 为什么需要共识SKILL

目前4个人各自萃取了1个案例，但：

| 问题 | 后果 |
|------|------|
| 4个人用的维度不一样 | 无法横向对比 |
| 萃取的颗粒度不同 | 有的粗有的细 |
| 水位判断标准不一致 | 你说L3他说L2 |
| 流程阶段命名不统一 | 无法对齐 |

### 6.3 案例萃取SKILL应包含什么

| 步骤 | 内容 | 产出 |
|------|------|------|
| **1. 案例筛选** | 什么样的案例值得萃取？ | 筛选标准 |
| **2. 信息提取** | 从逐字稿/录音中提取什么信息？ | 提取模板 |
| **3. 能力映射** | 如何把行为映射到4×7框架？ | 映射规则 |
| **4. 水位判断** | 如何给出L1/L2/L3的定位？ | 判断标准 |
| **5. 争议处理** | 判断不一致时怎么办？ | 争议处理流程 |

### 6.4 明天16:00会议建议

**议程建议**：

| 环节 | 内容 | 时间 |
|------|------|------|
| 1 | 4人各自展示案例萃取结果 | 40分钟 |
| 2 | 对比4个案例的萃取方式，找异同 | 20分钟 |
| 3 | 讨论共识：统一的萃取维度和标准 | 30分钟 |
| 4 | 整合SKILL初版 | 20分钟 |
| 5 | 下一步分工 | 10分钟 |

**关键问题**：
- 4个案例是否都能映射到4×7框架？
- 水位判断是否一致？不一致的地方在哪里？
- 消费者决策流程7个阶段的命名，4人是否认同？

## 七、学-练-评如何与4×7结合

### 7.1 S的学-练-评概念

> 快速产出学习者应该学习的内容 → 学完立刻进入练习 → 基于练习快速给出评价 → 循环继续。类似KTV点歌-唱歌-反馈的模式。

**核心特征**：
- 快速循环，不是"学完再练"
- AI辅助，降低内容产出成本
- 评价即时，不等期末考试

### 7.2 学-练-评与4×7的映射

| 环节 | 在4×7中的含义 | 具体做什么 |
|------|--------------|-----------|
| **学** | 学习一个阶段的能力要求 | 看示范案例（付振博）+ 理解框架定义 |
| **练** | 用自己的案例试填28格 | 拆解自己的案例，按4×7映射 |
| **评** | 水位判断：这个经纪人到哪了？ | 给出L1/L2/L3定位 + 短板识别 |
| **循环** | 继续下一个阶段或下一个案例 | 持续用新案例验证和迭代 |

### 7.3 工作坊中的学-练-评设计

| 环节 | 工作坊对应 | 时间 |
|------|-----------|------|
| **学** | 第一部分+第二部分：框架讲解 + 付振博案例示范 | 90分钟 |
| **练** | 第三部分Step 2-4：拆解自己的案例 | 55分钟 |
| **评** | 第三部分Step 5：共识收敛，给出水位判断 | 30分钟 |
| **循环** | 收束：约定后续持续验证 | 25分钟 |

### 7.4 工作坊之后的学-练-评

工作坊只是一次启动。真正的学-练-评循环是持续的：

```
城市经纪人在日常工作中遇到案例
    ↓
用4×7框架拆解（练）
    ↓
花桥/城市负责人给出水位评价（评）
    ↓
识别短板 → 针对性学习内容（学）
    ↓
下一个案例（循环）
```

**AI可以加速的环节**：
- 案例拆解的初稿（AI辅助萃取）
- 水位评价的初判（AI基于标准给出建议）
- 学习内容的快速生成（AI根据短板生成针对性内容）
