# 案例萃取SKILL：标准化方法论

> **目的**：让4人团队的案例萃取产出可比较、可整合，形成共识的语言和标准
> **版本**：v0.1
> **日期**：2026-06-08
> **关联项目**：[[4×7项目-项目现场]]

---

## 一、为什么需要标准化

| 问题         | 后果       |
| ---------- | -------- |
| 4个人用的维度不一样 | 无法横向对比   |
| 萃取颗粒度不同    | 有的粗有的细   |
| 水位判断标准不一致  | 你说L3他说L2 |
| 流程阶段命名不统一  | 无法对齐     |

**共识SKILL = 让4个人的萃取结果能放在同一张表上对比。**

## 二、萃取五步法

### Step 1：案例筛选

**什么样的案例值得萃取？**

| 维度       | 标准               | 说明              |
| -------- | ---------------- | --------------- |
| **完整性**  | 覆盖3个以上消费者决策阶段    | 能看到链路，不是片段      |
| **能力展现** | 至少有1个"判断"或"立场"时刻 | L1案例（纯信息搬运）价值有限 |
| **真实性**  | 有逐字稿或录音可回溯       | 不依赖记忆，要有源文件     |
| **争议性**  | 有可讨论的空间          | 完美无缺的案例不如有争议的案例 |

**优先级**：
1. 有反向判断的案例（敢说"别买/别卖"）
2. 有需求排序时刻的案例（C2阶段）
3. 失败案例（同样有价值——"哪里断了"）

---

### Step 2：信息提取

**从逐字稿/录音中提取什么？**

| 提取项         | 说明             | 格式        |
| ----------- | -------------- | --------- |
| **客户/业主画像** | 家庭结构、决策背景、预算约束 | 1-2句话     |
| **需求表达**    | 客户说了什么（原话）     | 原话引用      |
| **隐性需求**    | 客户没说但经纪人听出来的   | 1-3条      |
| **关键互动节点**  | 每个决策阶段的关键对话/事件 | 按阶段列出     |
| **经纪人判断时刻** | 给出明确结论的原话      | 原话引用+阶段标注 |
| **反向判断时刻**  | 敢说"别买/别卖"的时刻   | 原话引用      |
| **成交/失败结果** | 最终结果           | 1句话       |

### Step 3：能力映射

**如何把行为映射到4×7框架？**

**映射规则**：

| 规则 | 说明 |
|------|------|
| **1行为1标签** | 一个具体动作只映射到1个能力维度 |
| **先看动作再归类** | 不是先定义再找例子，是先看做了什么再判断属于哪类 |
| **必须有原话支撑** | 每个映射都要有逐字稿中的原话作为证据 |
| **缺位的也要记录** | 哪个阶段/维度没有展现，也要标注"缺失" |

**映射方法**：

| 你看到的行为 | 归类依据 |
|-------------|---------|
| 经纪人看到了客户没看到的 | → **理解** |
| 经纪人给出了明确结论 | → **判断** |
| 经纪人提供了具体下一步 | → **路径** |
| 经纪人站在客户长期利益 | → **立场** |

**常见争议**：
| 争议 | 处理方式 |
|------|---------|
| "这个动作既是理解又是判断" | 拆成两个动作：看见什么→理解，给什么结论→判断 |
| "判断和立场分不清" | 判断是"结论是什么"，立场是"结论站在谁那边" |
| "某个阶段没有行为" | 标注"缺失"，缺失本身就是信息 |

### Step 4：水位判断

**如何给出L1/L2/L3定位？**

**两步判断法**：

**第一步：Y轴判断（能力深度）**

| 层级 | 标准 | 检验问题 |
|------|------|---------|
| Y1 理解 | 看见客户没看见的 | 他说了什么客户没说出口的？ |
| Y2 判断 | 给出明确结论 | 他有没有给"你应该X"的判断？ |
| Y3 路径 | 提供可执行下一步 | 客户走出后能复述"接下来三件事"吗？ |

**第二步：X轴判断（立场强度）**

| 层级 | 标准 | 检验问题 |
|------|------|---------|
| X1 中转 | 传话筒，不站位 | 他说"业主说了算""您再考虑"了吗？ |
| X2 中性 | 列利弊，不偏 | 他说"ABC优点，XYZ缺点，您权衡"了吗？ |
| X3 立场 | 敢说违背自身利益的话 | 他有没有给过反向判断？ |

**第三步：综合定级**

> **综合 = 两个维度的最小值（短板决定）**

- 任意一维度L1 → 整体L1
- 两维度都至少中段 → L2
- 两维度都到顶端 → L3

**注意事项**：
- 水位判断基于**此次案例**，不跨案例推断
- 明确标注是Z1/Z2/Z3哪个层面
- 不确定时标注"待验证"，不强行定级

---

### Step 5：争议处理

**判断不一致时怎么办？**

| 情况      | 处理方式                |
| ------- | ------------------- |
| 能力映射不一致 | 回到原话：这个动作到底做了什么？    |
| 水位判断不一致 | 回到标尺：Y轴到哪？X轴到哪？     |
| 定义理解不一致 | 记录两种理解，不强行统一，留待共创讨论 |
| 案例信息不足  | 标注"信息缺失"，不猜测        |

**争议处理原则**：
- 争议本身是有价值的——它暴露了框架需要澄清的地方
- 不追求统一答案，追求"理解差异在哪"
- 争议点写入"争议清单"，作为四人会议和城市共创的讨论素材

## 四、4人会议中的使用方式

### 明天16:00会议建议议程

| 环节  | 内容                   | 时间   |
| --- | -------------------- | ---- |
| 1   | 每人5分钟：展示C2×判断的1个格子拆解 | 20分钟 |
| 2   | 对比4个版本的差异            | 20分钟 |
| 3   | 讨论共识：统一的萃取标准         | 30分钟 |
| 4   | 争议处理：不一致的地方怎么记       | 20分钟 |
| 5   | 下一步分工                | 10分钟 |

### 核心对齐问题

1. **C2×判断的拆法是否一致？** 4个人的"判断"定义一样吗？
2. **评价标准是否可共识？** "什么叫判断做到了"有2条以上大家认同的标准吗？
3. **水位判断是否一致？** 4个案例分别到哪个水位？依据是什么？
4. **萃取模板是否可用？** 上面的模板需要怎么调整？
